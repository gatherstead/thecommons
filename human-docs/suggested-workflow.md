# Suggested Workflow

> **Last updated:** 2026-08-05


This project was created primarily through claude. Of course best practices change quickly, so if 
feel free to change this in the future. Most evrything was generated by AI and it would not be 
feasible to rewrite this codebase to be more human friendly. Highly suggested to use AI to code 
and manually QA/ use claude in chrome (or any equivalent).

As of now though, docs are what drive this project forward. If docs don't exist or (even worse) docs are incorrect,
this system will fail. This project lives and dies by the docs! (kidding)

Good docs allow AI to parse through the codebase more efficently (less token spend) which helps keep context usage low and 
produce better outputs. So, make sure to update these regularly. 

Highly recommoend using and creating more devtools to help you, they are easy to spin up using AI. 


## Adding a new source

Should be done through the ingestion-playground devtool.
1. go to http://127.0.0.1:8000/devtools/ingestion-playground once your local is set up. 
2. for ICS links, you can test them straight up.
3. for html scrapers, create them locally then click through the dropdown to run it.
4. test to see if the events that are being collected are the right events/all of the available events from that source website. 
5. test to check the tags are the correct tags. 
6. If needed, adjust the system prompt- can be done in the devtool. This will append the instructions to gemini and hence will be 
processed differently. This adjustment will ONLY affect that collector, it won't effect everything so you don't have to keep in mind side effects.
7. Once you've turned it to your liking, click the 'copy VM command' and paste it directly in to the vm. This will populate everything accordingly,
from the name of the collector to the gemini prompt. 


## Monitoring Ingestion

There is a devtool for this, http://127.0.0.1:8000/devtools/monitor 
You won't need to parse through the database, you can check the status of things here. 


## General Coding

This is the most efficent way I've found to contribute to this project. 

the ticket writing skill writes parallelizable high detail tickets that encompass business motivation for the ticket, 
files that need to be changed, acceptance criteria, and ways to go about it. 

The orchestration skill helps claude use an orchestratior + devloper coding pattern to help prevent context rot and parallelize
code writing to help responses be more accurate and complete quicker.

### Usage
- suggest a feature in englishand use the command '/write-tickets' to create fleshed out tickets.
- copy the response, then use '/orchestrate' in a different claude instance to code the feature up.
